# 出门前

两个页面：今日提醒、提醒设置。Open-Meteo 实时天气，按北京时间校验当天预报；根据出门时段体感温度和个人偏好推荐具体搭配。设置与反馈仅在当前设备保存，反馈目前不自动改变规则。

## 交付状态

Sites 发布目录为 dist，提供天气网站、设置和本地系统测试通知。Sites 静态托管未接入常驻推送服务，因此不会声称每日推送已开启。**仅静态发布不能达到关闭网页后每天自动提醒的完成标准。**

仓库附有可运行的 Node 后台，包含 Web Push 订阅、凭证校验、持久化、每日调度、暂停、当天去重、失败重试、失效订阅清理和当天预报失败通知。必须将整个应用部署到支持常驻进程与持久磁盘的 HTTPS 主机，才能使用后台推送。当前没有配置或声称该主机已存在。

## 后台启用

1. 安装 Node.js 22+，运行 `npm install`。
2. 设置 `VAPID_SUBJECT` 为维护者真实联系邮箱（mailto:）或 HTTPS 联系页面。
3. 设置 `PUBLIC_ORIGIN` 为实际 HTTPS 网站来源，例如 `https://weather.your-domain.example`。设置 PORT（默认 4174）、DATA_DIR（默认 .runtime，必须持久化）。
4. 运行 `npm start`，使用反向代理提供 HTTPS，配置服务进程自动重启。
5. 保存城市、时间、偏好，允许系统通知并点击开启每日通知。每个设备单独订阅；手机系统支持情况不同，iOS 需要安装到主屏幕。

VAPID 密钥首次运行自动创建在 DATA_DIR/vapid.json。密钥与订阅数据均不能提交到代码库。使用一个服务实例；多实例应改用数据库原子任务认领。发送窗口为设定时间之后 15 分钟，窗口内每两分钟重试。推送服务接收成功不等于设备展示成功；操作系统、电源策略、网络和浏览器支持情况影响送达。进程在发送成功与持久化之间崩溃仍可能造成重复，通知使用固定 tag/topic 合并。

测试：`npm test`。系统通知的权限与真实端到端投递需要在用户设备和正式后台接通后验收。
